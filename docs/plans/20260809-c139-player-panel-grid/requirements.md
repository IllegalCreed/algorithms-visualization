## 背景与复现

C137/C138 完成左右同屏与阴影修复后，用户在「二分答案」页发现最右侧柱子压进代码面板。2048×1158 真浏览器测量显示：左侧视觉列宽 575.8px，但 11 根柱子的固有宽度为 660px；柱轨居中后右边界为 1269.9px，而代码面板左边界为 1243.8px，实际重叠约 26px。

用户同时提出把当前的「可视化 + 说明」拆为两个面板，与右侧「代码 + 变量」组成规整的两行两列布局。

## 用户故事

作为对照动画、字幕、代码和变量的学习者，我希望四类信息各有稳定边界并按两行两列对齐，任何可视化轨都不能覆盖代码面板；窄屏时则按阅读顺序自然堆叠。

## 要做什么

- 桌面播放器改成四面板：左上可视化、右上代码、左下步骤说明、右下变量。
- 让主柱轨在可用宽度不足时等比例缩小槽位，并保持柱子与箭头共用同一原点和槽宽。
- 为其他固有宽度较大的视觉轨提供面板内横向滚动边界，不能越过代码列。
- 保留代码内部滚动、变量区域行为、播放控制和当前步骤同步。
- 窄屏改为可视化 → 说明 → 代码 → 变量的单列顺序，不产生页面级横向溢出。

## 不做什么

- 不修改任何算法 module、`Step` 数据、字幕内容、代码源或路由。
- 不逐页复制布局；只改共享播放器与共享柱轨。
- 不通过裁掉柱子、降低右侧面板阴影或提高 z-index 掩盖重叠。
- 不在本变更中重做侧边目录、Header 或文章正文排版。

## 验收口径

1. `/docs/binary-answer` 在 1440px 桌面视口下，柱轨右边界不超过代码面板左边界。
2. 播放器桌面结构形成两列两行：visual/code 位于第一行，explanation/vars 位于第二行。
3. `BarsView` 的视觉宽度不超过父容器，所有柱槽与箭头仍按相同比例对齐；首尾柱均可见。
4. 900px 视口下四面板单列，`document.scrollWidth <= viewport`。
5. C137 同步、C138 阴影以及既有算法行为全部回归通过。

## 边界与异常

- 自定义输入允许 2~12 根柱；槽位可缩小，但数值、状态色和指针必须保留。
- 迷宫、筛法、棋盘等固有宽度轨允许在可视化面板内部横向滚动，不允许侵入相邻面板。
- 说明较长或出现 QuizCard 时允许第二行增高，变量面板仍与其处于同一网格行。

## 开放问题

无。用户已明确同意按四面板两行两列方向继续。

## 验收结果

- 1440px 桌面视口：11 根柱轨的右边界与代码面板左边界之间保留约 28px 间距，视觉/代码及说明/变量两行分别对齐。
- 1200px 桌面视口：仍保持双列，柱轨在视觉面板内按父宽收缩，不侵入代码面板。
- 900px 视口：四面板按可视化 → 说明 → 代码 → 变量单列排列，页面 `scrollWidth` 不超过视口宽度。
- 合并排序等带 auxiliary 轨的页面同样通过同屏与无内部溢出复核。
