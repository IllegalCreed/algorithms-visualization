## 背景

全量审计发现桌面端基线稳定，但 390px 手机宽度下 Header、Docs 目录和文章播放器仍受 600px 最小宽度与 300px 固定侧栏约束，正文被压缩到不可读。键盘快捷键、搜索弹窗焦点、结构互动表单语义、颜色对比度和动画偏好也存在可访问性缺口。部分英文页面还通过总模块桶产生异常预加载，路由父入口和滚动位置也有真实线上问题。

## 用户场景

- 手机用户打开中文或英文首页，可以完整看到标题、搜索、语言切换和主要入口。
- 手机用户进入任一算法页，可以打开目录抽屉、阅读正文、查看可视化、代码和变量，并用触控完成播放/单步/拖动。
- 键盘或读屏用户可以打开并关闭搜索、切换代码语言、操作结构互动控件，并得到动态结果播报。
- 用户从目录切换文章时，新页面从顶部开始；直接打开 `/docs`、`/en/docs` 不出现服务器 403/404。
- 桌面端现有双栏播放器、阴影、算法轨道和 190 页 SEO 行为保持不变。

## 要做什么

1. 建立共享响应式断点：手机、平板/窄桌面、宽桌面分别处理 Header、Home、Docs、Article 和 Player。
2. 手机端将目录改为可访问抽屉/Sheet，取消正文被固定侧栏挤压和嵌套滚动。
3. 手机端播放器改为纵向阅读与面板切换；控制条换行、触控目标扩大、代码保持可横向滚动。
4. 修复播放器快捷键、搜索 dialog 焦点、路由切换焦点/滚动、代码语言 tab 语义。
5. 为结构输入、动态 status、节点操作、复杂度筛选和面板标题补语义与播报。
6. 补对比度、forced-colors、reduced-motion、safe-area 和图片尺寸/lazy loading 支持。
7. 修复英文模块总桶导入、首页同步导入和可测量的 CSS 重复；加入产物预算。
8. 为自有域增加安全响应头断言；依赖升级单独受控，不使用无审查的自动大版本迁移。

## 不做什么

- 不改变任何算法 oracle、步骤序列、代码内容、输入协议、测验答案或 SEO catalog 口径。
- 不为 92 个算法页面逐页复制响应式实现；共享组件优先。
- 不在本变更中引入完整暗色主题；只清理死状态或为后续主题保留明确边界。
- 不改变 GitHub Pages 的平台能力边界；无法设置的响应头记录为平台限制。

## 验收口径

- 360×800、390×844、430×932、844×390 下中文/英文首页与至少 3 类算法页无横向页面溢出，正文可读，目录可打开/关闭。
- 手机播放器能完成重置、上一步、播放、下一步、速度、循环、拖动进度、切换语言；焦点在按钮上按 Space 不触发全局播放快捷键。
- 搜索 dialog 满足 Escape、Tab 循环、触发按钮焦点恢复、背景不可操作。
- 文档路由切换后 `#right`/页面滚动回到顶部；`/docs` 和 `/en/docs` 直接访问为 200 并进入明确默认页或重定向。
- 现有桌面布局、阴影、190 页预渲染、中文/英文目录与算法交互回归全绿。
- 初始英文播放器页不再预加载全部 77 个英文模块；构建产物预算测试能阻止回退。
- `pnpm verify`、`pnpm coverage`、移动/桌面 Playwright 全套通过；无新增 lint/type 错误。

## 边界与异常

- 低于 360px 允许内容在代码/矩阵内部横向滚动，但页面本身不得横向溢出。
- 密集 SVG/矩阵/代码轨道不强行缩小到不可读，可提供横向平移或全屏查看。
- `prefers-reduced-motion` 下保留步骤状态变化，关闭连续 FLIP/脉冲动画。
- Analytics consent banner 必须尊重 `safe-area-inset-bottom`，不得遮挡播放器主控制。
