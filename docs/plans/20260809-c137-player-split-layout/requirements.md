## 背景与复现

算法文章页左侧目录占据固定宽度，右侧正文中的 `AlgorithmPlayer` 当前按“可视化 → 代码/变量”纵向排列。用户在阅读算法步骤时必须上下滚动，无法同时对照动画和当前代码。实测 1200px/1280px 视口时右侧内容分别约 860px/940px；现有播放器还因 1400px 断点把代码与变量强制改成纵向。

## 要做什么

- 在有足够内容宽度的桌面视口，把可视化轨与代码/变量检查区放入同一播放器舞台：左侧可视化，右侧代码与变量。
- 代码区随步骤继续高亮，并在代码较长时在自己的滚动容器内保持当前高亮行可见。
- 右侧检查区在正文滚动时保持可见，但不遮挡全局头部；变量较多时只在自身区域滚动。
- 在窄桌面、平板和手机上自动退回纵向堆叠，保证不产生横向溢出、不缩到不可读。
- 通过 `Article` 的共享样式自动放宽包含播放器的文章，不修改 77 个算法页面的正文结构。
- 不改变算法 module、步骤顺序、播放器控制、测验语义或英文页面路由。

## 不做什么

- 不为每个算法页复制一套布局或改写播放器数据轨。
- 不把代码字体压缩到无法阅读，也不强制整个正文固定为宽屏。
- 不在窄屏用横向滚动隐藏代码或可视化。

## 业务规则与验收口径

1. 桌面双栏只在可用内容宽度能容纳可视化和约 300px 检查区时启用；布局阈值以右侧内容实际空间为准。
2. 同一步的可视化、代码高亮和变量值必须仍由同一个 `current`/`point` 驱动。
3. 任何没有可选轨的旧 module 仍只渲染自己声明的轨，不能因容器改造产生空面板。
4. 代表性图算法页（Dijkstra）在桌面双栏和 900px 窄屏都必须可操作；桌面测量同时存在 graph 与 code，窄屏不横溢出。
5. 通过 L4 定向测试、L5 浏览器布局测试、类型/格式/单测门禁后，才能标记 verified。
